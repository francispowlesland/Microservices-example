# Build prompt 00: shared platform and conventions

Run this **once, first**. The four service prompts (`01-users.md` to `04-inventory.md`) assume everything here exists and follow the conventions below. If you are building a service prompt and `internal/platform/` is missing, stop and run this one.

## Context

- Repo root: `microservices-app-go/`. Single Go module, already initialised: `github.com/francispowlesland/microservices-app-go` (`go.mod` at the root).
- gRPC contracts live in `proto/` and are **already generated** into `gen/go/` (Go packages `userv1`, `ordersv1`, `paymentsv1`, `inventoryv1`). Do not edit `proto/` or `gen/`. If a contract is genuinely insufficient, stop and report it rather than changing it.
- `services/gateway` is a SvelteKit app. Out of scope.
- Use the Go version in `go.mod`. Prefer the standard library: `log/slog`, `net`, `context`, `errors`, `os`. No web frameworks, no config frameworks (no viper), no ORMs, no `protovalidate`.

## Fixed decisions

| Concern | Decision |
|---|---|
| Transport | gRPC over HTTP/2 (`google.golang.org/grpc`), plaintext inside the cluster |
| Database | PostgreSQL, **one database per service**, driver `github.com/jackc/pgx/v5` (`pgxpool`). Hand-written SQL, no ORM |
| Migrations | `github.com/pressly/goose/v3`, SQL files embedded with `go:embed`, applied on startup |
| IDs | UUIDs (`github.com/google/uuid`), generated by the service, stored as `uuid` |
| Auth tokens | JWT, **EdDSA (Ed25519)**, `github.com/golang-jwt/jwt/v5`. Users service signs, every service verifies with the public key |
| Pagination | Keyset on `(created_at, id)`, opaque base64 page token. Default page size 50, max 200 |
| Money | `int64` minor units (cents). Never floats |
| Roles | `admin` and `customer`. Carried in the JWT `roles` claim |
| Ports | users `50051`, orders `50052`, payments `50053`, inventory `50054` (the gateway's defaults) |

## Deliverables

### 1. `internal/platform/config`
Tiny env helpers: `String(key, default)`, `Required(key)`, `Duration(key, default)`, `Int(key, default)`. Return errors rather than panicking; `main` decides what to do.

### 2. `internal/platform/authn`
- `Claims{Subject string; Roles []string}` with `IsAdmin()` and `HasRole(string)`.
- `Signer` (Ed25519 private key, issuer, audience, TTL) with `Sign(userID string, roles []string) (token string, expiresAt time.Time, err error)`.
- `Verifier` (Ed25519 public key, issuer, audience) with `Verify(token string) (Claims, error)`. Must reject any algorithm other than EdDSA, expired tokens, and wrong issuer or audience.
- Constants: issuer `microservices-app/users`, audience `microservices-app`.
- `ParsePrivateKeyPEM` and `ParsePublicKeyPEM` (PKCS#8 and PKIX).
- `UnaryInterceptor(v *Verifier, public map[string]bool) grpc.UnaryServerInterceptor`:
  - Reads `authorization: Bearer <jwt>` from incoming metadata.
  - **Default deny.** Methods in `public` (full method names such as `/user.v1.AuthService/Login`) skip auth. Everything else needs a valid token, otherwise `codes.Unauthenticated`.
  - Puts `Claims` in the context.
- `FromContext(ctx) (Claims, bool)` and `MustFromContext(ctx) Claims`. The `Must` form panics only if the interceptor was bypassed (a wiring bug); the recovery interceptor turns that into `codes.Internal`.
- Unit tests: sign/verify round trip, expired token, wrong audience, `alg=none`, wrong key, missing header, public method bypass, default deny.

### 3. `internal/platform/pagination`
- `Encode(createdAt time.Time, id uuid.UUID) string` and `Decode(token string) (time.Time, uuid.UUID, error)`. The empty token means "first page".
- `PageSize(requested int32) int` clamps to default 50 and max 200. Zero or negative means default.
- Callers fetch `size+1` rows to decide whether to emit `next_page_token`.
- The token is **not** a trust boundary. Filters such as `user_id` must be re-applied on every page from the request and the caller's claims, never read from the token.
- Unit tests, including malformed tokens.

### 4. `internal/platform/pgxutil`
- `Connect(ctx, databaseURL) (*pgxpool.Pool, error)` with a ping, and sensible pool settings.
- `Migrate(ctx, databaseURL string, fsys fs.FS, dir string) error` using goose with the embedded filesystem.
- `IsUniqueViolation(err error, constraint string) bool` using `pgconn.PgError` code `23505`.
- `IsNotFound(err error) bool` for `pgx.ErrNoRows`.
- Test helper (build-tagged or in a `pgxtest` subpackage): start a throwaway Postgres with `testcontainers-go` (`modules/postgres`) and return a connection URL. It must `t.Skip` under `go test -short` and when Docker is unavailable.

### 5. `internal/platform/grpcx`
`Run(ctx, cfg, register func(*grpc.Server)) error`:
- Listens on `cfg.Addr`, builds a `grpc.Server` with a **unary** interceptor chain: recovery (panic to `codes.Internal`, logged with stack), request logging via `slog` (method, code, duration, peer; **never** request or response bodies), then `authn` when a verifier is supplied.
- Registers the standard health service (`google.golang.org/grpc/health`) as SERVING, and reflection **only** when `APP_ENV != production`.
- Graceful shutdown on `ctx` cancellation: `GracefulStop` with a timeout, then `Stop`.
- Only unary interceptors are installed, so the streaming health Watch and reflection endpoints are naturally unauthenticated.

### 6. Docker support in the platform
- `pgxutil.Connect` and `Migrate` retry with a capped backoff (see the Dockerfile section above).
- `grpcx` exposes `HealthCheck(addr string, timeout time.Duration) error`, which each service's `main` calls for the `healthcheck` subcommand.
- Create the repo-root `.dockerignore` described above.

### 7. `tools/keygen`
`go run ./tools/keygen` prints an Ed25519 keypair as PEM (PKCS#8 private, PKIX public), clearly labelled, for use as `JWT_PRIVATE_KEY` and `JWT_PUBLIC_KEY`.

## Conventions every service must follow

**Layout**
```
services/<name>/
  cmd/<name>/main.go        wiring only: config, pool, migrate, grpcx.Run
  internal/config/          typed config from env
  internal/service/         gRPC handlers + business rules; depends on a small Store interface
  internal/store/           pgx implementation of that interface
  migrations/               *.sql (goose) + embed.go exposing an embed.FS
  Dockerfile                see "Dockerfile (all services)" below
  README.md                 env vars, how to run, how to test
```

**Layering and testing**
- Handlers embed the generated `Unimplemented<Name>ServiceServer` and register with the generated `Register...Server`.
- Business logic and authorisation live in `internal/service`. SQL lives only in `internal/store`.
- `internal/service` is unit-tested against an in-memory fake of the `Store` interface. `internal/store` is tested against real Postgres via the shared test helper (skipped under `-short`).
- Table-driven tests. Cover the authorisation matrix, each error code, and pagination.

**Errors**
- Handlers return only `status.Error(...)` values. Never leak SQL, driver, or stack details to callers. Log the real error server-side and return `codes.Internal` with "internal error".
- Mapping: bad input to `InvalidArgument`; missing row to `NotFound`; unique violation to `AlreadyExists`; no token to `Unauthenticated`; valid token but not allowed to `PermissionDenied`; state-machine violations to `FailedPrecondition`.
- For resources owned by a user, return `NotFound` rather than `PermissionDenied` when a non-admin asks for someone else's row, so IDs cannot be probed.

**Validation**
- IDs must parse as UUIDs, otherwise `InvalidArgument`.
- Trim and length-limit every string. Validate at the service boundary, not in the store.

**Logging and secrets**
- `slog` JSON handler. Never log passwords, tokens, hashes, or reset/verification tokens (except where a service prompt explicitly says dev-only).

**Dockerfile (all services)**

Each service ships its own `services/<name>/Dockerfile`. They will be orchestrated later with docker-compose, **with one Postgres container per service**. Compose itself is out of scope here, so do not write it. The image must work with it.

- **Build context is the repo root** (the module, `gen/` and `internal/platform/` are shared). Build with `docker build -f services/<name>/Dockerfile .` from the root. State this command in the service README.
- **Multi-stage.** Builder: `golang:<version from go.mod>` (pin the minor version, no `latest`). Copy `go.mod` and `go.sum` first and run `go mod download` so the dependency layer caches. Then copy only what is needed (`gen/`, `internal/`, `services/<name>/`), and build with `CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o /out/<name> ./services/<name>/cmd/<name>`.
- **Final image:** `gcr.io/distroless/static-debian12:nonroot`. It runs as non-root, has no shell, and contains only the binary. Migrations are embedded, so no extra files are copied.
- `EXPOSE` the service's gRPC port. `ENTRYPOINT ["/<name>"]` in exec form, so signals reach the process and graceful shutdown works.
- **No secrets in the image or build args.** `DATABASE_URL`, `JWT_PRIVATE_KEY` and `JWT_PUBLIC_KEY` are supplied at runtime only. The Dockerfile may set non-secret defaults such as `GRPC_ADDR` and `APP_ENV=production`.
- **Health check without a shell.** Distroless has no `curl` or `grpc_health_probe`, so give each binary a `healthcheck` subcommand: `/<name> healthcheck` dials `GRPC_ADDR` (on localhost), calls the standard `grpc.health.v1.Health/Check`, and exits `0` if SERVING and `1` otherwise, with a short timeout. Wire it with `HEALTHCHECK CMD ["/<name>", "healthcheck"]`. Compose can reuse the same command.
- **Startup against a not-yet-ready database.** In compose the service and its Postgres start together. `pgxutil.Connect` and `Migrate` must retry with a capped backoff (about 30 seconds in total) before giving up and exiting non-zero, so the container does not need `depends_on` ordering to succeed.
- Add a `.dockerignore` at the repo root (once, in prompt 00) excluding `.git`, `**/node_modules`, `services/gateway`, `.svelte-kit`, `prompts/` and `*.md`, so the context stays small.
- **Verify:** `docker build` succeeds, the image is under about 40 MB, `docker run` as a non-root user works, and the container exits cleanly on `docker stop`. Run it once against a throwaway Postgres container to confirm migrations apply and the health check goes healthy.

**Config (all services)**
- `GRPC_ADDR` (default `:<port>`), `DATABASE_URL` (required), `APP_ENV` (`development` or `production`, default `development`), `JWT_PUBLIC_KEY` (PEM, required except in users, which derives it from its private key).

## Dependencies to add (with `go get`, then `go mod tidy`)
`google.golang.org/grpc`, `github.com/jackc/pgx/v5`, `github.com/pressly/goose/v3`, `github.com/google/uuid`, `github.com/golang-jwt/jwt/v5`, `golang.org/x/crypto` (users only), `github.com/testcontainers/testcontainers-go` and its `modules/postgres`. Nothing else without a reason.

## Done when
- `gofmt -l .` prints nothing.
- `go build ./... && go vet ./... && go test -short ./...` pass.
- `go test ./internal/platform/...` passes with Docker running.
- `.dockerignore` exists at the repo root.
- No file under `proto/` or `gen/` changed (`git status` confirms).
